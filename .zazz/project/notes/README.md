# Project notes

Working notes for developing and maintaining this lab: where the work stands, why things are the way they are, and what a work session found. They are not documentation for readers of the lab. Anything a reader needs belongs in the [README](../../../README.md) or in [`docs/`](../../../docs/), and a note links to it instead of repeating it.

## Rules

- A note is one Markdown file named `<UTC date-time>_<topic>.md`, for example `2026-11-25T21-55-02Z_project-state.md`. Its first line repeats the date-time with the local offset.
- A note is an entry, not a living page. When something it says no longer holds, write a new note and move the old one to *Superseded* below.
- A note says what the documentation does not: a decision and its reason, a measurement, the state of the work, a lesson.
- `.zazz/ephemeral/` is ignored by git. It holds scratch files and handoffs that stay on the machine.
