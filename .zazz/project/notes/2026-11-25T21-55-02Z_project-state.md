## Why the pins are pins

The invariants are in [AGENTS.md](../../../AGENTS.md). The reasons behind two of them:

- The main app stays on Next.js 13.4.19, React 18.2.0 and the Pages Router because the upstream scenarios were written for them. A migration would move the source locations the tools are tested against.
- `targets/react2shell` stays on next 15.0.4 and React 19.0.0 because the vulnerable pin is the scenario.

Dependencies are pinned exactly, and a dependency change moves the audit snapshot.

## Environment

- Node 24 LTS. pnpm 11.25.0 comes from corepack, so commands are written `corepack pnpm …`.
- The first MongoDB request downloads `mongod` (MongoDB 8.2.6, about 80 MB).
- Both apps bind `127.0.0.1` only: the main lab on port 3000, the fixture on 3001.
- `pnpm test:api` and `pnpm test:browser` reuse a server that is already listening on port 3000. Otherwise they start `pnpm start` from the existing build, so rebuild before running them on a change.
- Stop a server as a whole. Killing only the process that listens on port 3000 leaves the Next.js render workers and `mongod` running. On 2026-11-25 two `next-render-worker-*` processes were found hours old, with process ID 1 as their parent.

## Measured on the test server

MongoDB 8.2.6 with driver 7.9.1 and `mongodb-memory-server` 11.4.0, measured on 2026-11-25:

- `collection.mapReduce` does not exist. `db.command({ mapReduce })` runs and accepts `scope`.
- `$accumulator` with `lang: 'js'` runs.
- `collection.count` exists and runs.
- An operator object inside an `$in` or `$nin` array is refused with `cannot nest $ under $in`. That covers operator documents only. A BSON regular expression inside `$in` is evaluated as a pattern.

Three safe routes of the second batch rely on that refusal, in whole or in part: `desk/unlock`, `loans/bundle` and `people/others`. They read JSON bodies, which cannot carry a regular expression, so the refusal holds for every input they can receive. A new route that builds regular expressions from text and feeds `$in` would not have it.
